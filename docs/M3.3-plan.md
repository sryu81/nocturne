# M3.3 — Module settings (Camera/Focus/Mount/Align/Guide) + Observatory control

## Context

Real Ekos's main window has six per-module tabs: Camera, Focus, Mount,
Align, Guide, Observatory. Nocturne's "Module assignments" card (M3.2)
only covers *which optical train each module uses* (`train_set`) — none of
each module's actual imaging-session parameters are exposed anywhere in
the app. This plan closes that gap with a **curated subset**, not full
parity — each real module's settings dialog has 17–98 fields, the large
majority of which are one-time-calibrate-and-forget tuning (PID gains,
astrometry index-file toggles, V-curve mask parameters) rather than
per-session decisions a phone remote needs to touch.

Two research passes preceded this plan, following the project's established
norm of confirming against the real thing rather than trusting docs alone:

1. **Protocol facts**, read from the real KStars source checkout
   (`~/cc/repo/kstars/kstars/ekos/ekosremote/{commands.h,message.cpp}`):
   every module except Observatory has a `<module>_get_all_settings` /
   `<module>_set_all_settings` command pair already in the wire protocol.
   Observatory/Dome has **no settings command at all** — only
   `dome_park`/`dome_unpark`/`dome_goto`/`dome_stop` (control, not config),
   confirming it needs no settings sheet, only a Bench control card.
2. **Real field data**, captured live against the rig (`*_get_all_settings`
   sent directly over the wire, Ekos already running): Capture 59 fields,
   Focus 84, Mount 17, Guide 84, Align 98. Full dumps kept in this session's
   transcript; the curated subsets below are what's left after excluding
   fields Bench/Sequence/Autofocus-Rules already cover, one-time
   calibration internals (RA/DEC PID gains, GPG predictive-guiding math,
   astrometry index-file installs), and KStars-desktop-only conveniences
   (`locationSource`, `timeSource`, etc. — meaningless remotely).

**Safety fact that de-risks the whole "curated subset" approach**: read
server-side (`Mount::setAllSettings`, `Camera::setAllSettings`, etc. in
`kstars/ekos/{mount,capture,...}/*.cpp`) — each iterates only the keys
*present* in the map you send (`for (auto &name : settings.keys())`) and
touches nothing else. Sending a 6-field subset of Capture's 59 cannot blank
out the other 53 — this is the same partial-write safety already relied on
for the cooler-setpoint fix (`capture_set_all_settings` with just the two
temperature fields).

Three decisions the user made, taken as given below:
1. Curated field lists as proposed (no trims/additions before starting).
2. UI placement: **new standalone Gear-tab card per module**, not folded
   into Module Assignments' existing rows.
3. Build order starts with **Mount** (smallest field set, cleanest
   mapping — validates the pattern before the bigger modules).

## Curated fields per module

**Mount** (9 of 17 — the rest are desktop-only conveniences):
`executeMeridianFlip`, `meridianFlipOffsetDegrees`, `enableAltitudeLimits`,
`minimumAltLimit`, `maximumAltLimit`, `enableAltitudeLimitsTrackingOnly`,
`enableHaLimit`, `maximumHaLimit`, `parkEveryDay`, `autoParkTime`.
(10 listed — `parkEveryDay`+`autoParkTime` pair as one control.)

**Camera** (6 of 59 — exposure/bin/gain/offset already live via Sequence
block editor; cooler temp already live via Bench):
`fileDirectoryT` (save path — not configurable anywhere in-app today),
`enforceGuideDeviation` + `guideDeviation`,
`enforceStartGuiderDrift` + `startGuideDeviation`,
`enableDitherPerJob` + `guideDitherPerJobFrequency`.

**Focus** (5 of 84 — excludes V-curve/CFZ/mask tuning, which needs graphs
to use meaningfully):
`focusExposure`, `focusGain`, `focusFilter`, `focusBacklash`,
`focusAlgorithm`.

**Align** (5 of 98 — excludes ~50 astrometry index-file booleans and
PAH*/solver internals; PAH* fields are the eventual real data source for
the still-fixture-only PA tab, a separate future integration):
`alignExposure`, `alignGain`, `alignFilter`, `alignBinning`,
`alignAccuracyThreshold`.

**Guide** (6 of 84 — excludes ~78 RA/DEC PID gains and GPG
predictive-guiding math, which are calibrate-once, not per-session):
`guideExposure`, `guideGain`, `guiderAccuracyThreshold`,
`kcfg_DitherEnabled`, `kcfg_DitherPixels`, `kcfg_DitherThreshold`,
`kcfg_ReuseGuideCalibration`. (7 listed.)

**Observatory**: no settings surface — protocol has none. Control only
(see below).

## Control side → Bench check

Existing Bench cards: Snap main/guide, Cooler, Focuser jog, Mount
jog/slew. Gaps this plan closes:

- **Align**: `ctrl.plateSolveHere()` already sends `align_solve` but is
  only wired into the fixture-only PA sheet. Add a Bench "Solve" card
  using the same method.
- **Guide**: no start/stop control anywhere; `Commands.kt` doesn't even
  define `GUIDE_START`/`GUIDE_STOP` yet (only `GUIDE_CAPTURE` exists).
  Add both, plus a Bench card.
- **Observatory**: `setDomeOpen` exists only as a Gear-tab button
  (`CloseRoofButton`, `GearScreen.kt`) and **is not wired to the real wire
  at all** — `Commands.kt` has no `DOME_PARK`/`DOME_UNPARK`/`DOME_GOTO`/
  `DOME_STOP` constants. Move it into Bench and wire it for real.

## Architecture

- `Commands.kt`: add `FOCUS_GET/SET_ALL_SETTINGS`, `MOUNT_GET/SET_ALL_SETTINGS`,
  `GUIDE_GET/SET_ALL_SETTINGS`, `ALIGN_GET/SET_ALL_SETTINGS` (Capture's pair
  already exists), `DOME_PARK`/`DOME_UNPARK`/`DOME_GOTO`/`DOME_STOP`,
  `GUIDE_START`/`GUIDE_STOP`.
- `SimState`: one small typed data class per module holding **only the
  curated fields** — not a raw `Map<String, Any>` mirroring the full
  17–98-field wire payload. E.g.:
  ```kotlin
  data class WireMountSettings(
      val executeMeridianFlip: Boolean, val meridianFlipOffsetDegrees: Double,
      val enableAltitudeLimits: Boolean, val minimumAltLimit: Double, val maximumAltLimit: Double,
      val altLimitsTrackingOnly: Boolean,
      val enableHaLimit: Boolean, val maximumHaLimit: Double,
      val parkEveryDay: Boolean, val autoParkTime: String,
  )
  ```
  Field-name mismatches between wire keys (camelCase, some prefixed
  `kcfg_`) and Kotlin property names are resolved in the decode step, same
  as `WireTrain`/`WireProfile` already do elsewhere.
- `SessionController`: one setter per module (`setMountSettings(...)`,
  `setCameraSessionSettings(...)`, etc. — named to avoid clashing with
  existing `setBlockExposure` etc.), same optimistic-then-reconcile
  pattern as `setModuleTrain`: fire `<module>_set_all_settings` with just
  the changed field(s), update local state immediately, reconcile off the
  next `<module>_get_all_settings` push.
- New `SheetType.MODULE_SETTINGS` parameterized by module key (mirrors
  `SheetType.DEVICE`'s `deviceKey` pattern) — one sheet body, dispatches
  its curated form by module key, reached from its own new Gear-tab card
  per module (5 new small cards: Camera/Focus/Mount/Align/Guide settings —
  Observatory gets no settings card since it has none).
- Bench additions: `AlignCard` (Solve button, real-wired via existing
  `plateSolveHere`), `GuideCard` (start/stop, newly wired), `ObservatoryCard`
  (dome open/close, moved from Gear tab and newly wired for real).

## Phasing

Each phase is independently shippable and live-verified against the real
rig before moving to the next, per this project's established norm (live
testing catches what source-reading alone doesn't — see prior bugs #1–#6
in project memory).

1. **Mount settings** — smallest field set (10), cleanest mapping. Ships
   the whole pattern (Commands.kt consts, SimState data class, controller
   setter, new sheet type, new Gear card) end-to-end once, so phases 2–6
   are mostly repetition of an already-proven shape.
2. **Observatory control → Bench** — small, self-contained, fixes a real
   gap (dome control currently doesn't touch the wire at all).
3. **Align**: Solve → Bench card, + Align settings sheet.
4. **Guide**: start/stop → Bench card (+ new `GUIDE_START`/`STOP` consts),
   + Guide settings sheet.
5. **Camera settings** (save dir, guide-deviation guard, dither) — extends
   already-real Capture wiring.
6. **Focus settings** — last; least session-blocking of the six.

## Testing

- Unit tests per module settings decode (mirrors `EkosEventCodecTest`'s
  byte-for-byte live-captured-payload style) using the real field dumps
  already captured this session.
- Live verification against the real rig after each phase — build+install
  on the emulator, connect to the real Pi, exercise the new sheet/card,
  confirm no crash and that a written value round-trips through the next
  `_get_all_settings` push, matching the methodology used for the
  Camera-Primary-snap-back fix and the device-sheet crash fix.

## Addendum (2026-08) — Controls tab supersedes per-module Gear cards

This plan's original UI placement — "5 new small Gear-tab cards" (see
Architecture above) — is superseded by a dedicated 6th top-level tab,
**Controls**. Mount/Camera settings (phases 1, 5) are done and unchanged
functionally — only relocated from Gear to Controls. Bench check's live
controls (snap/cooler/focuser jog/D-pad/rate chips/unpark/plate-solve)
moved into the matching Controls section instead of staying on their own
Bench sheet; `SheetType.BENCH`/`BenchSheet` are deleted.

Two things explicitly **not** part of this restructure, still out of
scope: **Observatory** (dome control, phase 2 — `CloseRoofButton` stays on
Gear tab, still not wired to the real wire at all) and **Focus settings**
(phase 6 curated field list — distinct from the focuser jog/autofocus
control, both of which live in Controls' Primary Camera section — see
below).

### Addendum 2 (2026-08, cont'd) — 4-section reorg + real Autofocus/Guide/Polar-Align

Controls tab's sections were regrouped a second time, from the original
4 (Primary Camera/Guide/Mount/Align) to a different 4:
1. **Primary Camera** — snap/cooler/focuser (now incl. real Autofocus
   start/stop, `focus_start`/`focus_stop`) + Camera settings + Plate
   Solving (the old Align section's `align_solve`/Align settings, folded
   in here — no longer a separate top-level section).
2. **Mount** — unchanged.
3. **Guide** — snap + real Guide start/stop (`guide_start`/`guide_stop` —
   `guide_stop` maps server-side to `abort()`, not a graceful pause).
4. **Polar Alignment** — moved from Gear tab (was `PaCard`/`PaSheet`,
   100% fixture) and given real wiring (`polar_start`/`polar_stop`).
   **Correction to this doc's earlier statement above**: Polar Align did
   *not* stay on Gear tab untouched — it moved, and Controls' plate-solve
   grouping (item 1) is the thing that inherited the "Align" name
   collision warning that used to apply between Align and PA; that
   warning is now moot since PA has its own dedicated section.

All three new controls (Autofocus/Guide/Polar-Align) use the same
architecture: a client-side optimistic boolean drives the Start/Stop
button's own label (never derived from the real wire status/stage
string, since none of those values are documented anywhere), and the raw
wire text is shown verbatim alongside as supplementary info. Real Polar
Align specifically shows raw `new_polar_state` stage/message passthrough
rather than a stage-driven wizard — confirmed live via probe that real
stages are independent partial pushes (`{"stage":"First Capture"}` then
separately `{"message":"..."}`, etc.) with no documented full vocabulary,
so mapping them onto fixed step-pills would be a wire-shape guess (same
class of mistake `WireAlignSettings`'s `alignBinning` type history
warns against).

`EkosEvent.NewPolarState` also got a decode-robustness fix as part of
this work: it had no field defaults, so every one of the real partial
payloads above used to fail to decode and silently fall back to `Raw` —
meaning `wirePolarStage` never actually updated on a real rig, caught by
inspection before ever shipping real Polar Align wiring, not from a bug
report.

### Addendum 3 (2026-08, cont'd) — Guide settings sheet closes out phase 4

Phase 4's remaining half (Guide start/stop shipped in Addendum 2; the
settings sheet itself was still open) is done: `WireGuideSettings` extended
from 3 fields (preview exposure/gain/binning) to 8, adding
`guiderAccuracyThreshold`, `kcfg_DitherEnabled`, `kcfg_DitherPixels`,
`kcfg_DitherThreshold`, `kcfg_ReuseGuideCalibration`. New `GuideSettingsCard`
(Controls tab, Guide section, real-rig gated) opens `GuideSettingsSheet` —
same shape as `AlignSettingsSheet`/`CameraSettingsSheet`.

**This doc's own field list above (§"Curated fields per module") was
unverified and risked being wrong**, not just untyped: `guiderAccuracyThreshold`
was the only one of the 5 dither/calibration fields present in
`EkosRemote-Command-Reference.md`'s own static-analysis field list (which
that doc explicitly flags as "not live-verified, unlike Capture/Focus"), and
`kcfg_ReuseGuideCalibration`'s un-prefixed near-namesake, `reuseCalibration`,
is a documented request field of a *different* command
(`guide_set_calibration_settings`), raising a real risk of sending the wrong
key to the wrong command entirely. A live probe of `guide_get_all_settings`
before writing any code confirmed all 5 names/the command choice were
actually correct as originally listed — a near-miss, not a mistake, but one
only avoided by probing first rather than trusting either doc.

Live-verified end-to-end against the real rig: sheet showed real values
matching the probe exactly (`±2"`, dither off, reuse-calibration on).
Toggled Dither on — sub-fields (amount, settle threshold) appeared, real
Ekos setting confirmed changed via an independent force-stopped probe
(`kcfg_DitherEnabled: true`), then toggled back off to restore original
state. Simulator smoke test: card absent entirely (correctly gated on
`isRealRig`), no crash.

M3.3 phase 4 (Guide) is now fully done. Remaining phases: 2 (Observatory/
dome — zero real wiring today) and 6 (Focus settings — distinct from the
already-real focuser jog/autofocus control).
